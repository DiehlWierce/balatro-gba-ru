# Прогон рома в эмуляторе без экрана

Скриптовые smoke-тесты на mGBA: ром запускается без окна, кнопки нажимаются по сценарию,
скриншоты сохраняются в PNG. Подходит для проверки «Готово, когда» по фиксированному сиду
и для сравнения двух сборок кадр в кадр.

## Установка (Ubuntu)

```bash
sudo apt install libmgba-dev libpng-dev python3-pil
```

`run.py` сам соберёт `gbarun` из `gbarun.c` при первом запуске.

## Запуск

Сначала собрать ром (`docker compose run gbalatro`), потом:

```bash
python3 ru-tools/emu/run.py ru-tools/emu/scenarios/smoke_shop.txt /tmp/shots
```

Для адресов в сценарии нужен ARM-тулчейн. Если задан `$DEVKITARM`, `run.py` берёт его,
иначе запускает команды в образе проекта через `docker compose run gbalatro`.

## Сценарии

| Файл | Что проверяет |
|---|---|
| `scenarios/smoke_shop.txt` | Сид `GBARU1`: блайнд пройден (счёт подставлен), награды, лавка, описание и покупка джокера, переход к следующему блайнду |
| `scenarios/smoke_lose.txt` | Сид `GBARU1`: четыре руки из пяти левых карт без подсказок, экран поражения |
| `scenarios/decks.txt` | Все 6 колод в настройке забега (стрелки влево/вправо), забег на Зелёной колоде: $2 за руку, $1 за сброс, без процентов |
| `scenarios/black_deck_six_jokers.txt` | Чёрная колода: 6 джокеров в ряду, седьмой не покупается, продажа из полного ряда |
| `scenarios/boss_round.txt` | Выбранный босс (`-D boss=N`): подпись на экране выбора блайнда, раунд: 1 карта, 5 карт, сброс, снова 1 карта |
| `scenarios/boss_reset.txt` | Выбранный босс (`-D boss=N`) побеждён: в следующем раунде руки, сбросы и размер руки обычные |
| `scenarios/stakes.txt` | Выбор ставки (L/R) с переходом по кругу; Золотая ставка на анте 3: цель 3200 (таблица Фиолетовой), Малый блайнд без награды, −1 сброс, стикеры джокеров в лавке |
| `scenarios/stake_stickers.txt` | Золотая ставка: аренда за $1 и −$3 в конце раунда, вечного джокера нельзя продать, скоропортящийся считает раунды |
| `scenarios/boss_jokers.txt` | Боссы с джокерами (`-D boss=25/26/28`: Жёлудь, Лист, Сердце): покупка джокеров, раунд с боссом, продажа джокера, после раунда всё как было |
| `scenarios/boss_pillar.txt` | Столп (`-D boss=19`): карты, сыгранные на Малом блайнде, на Биг блайнде того же анте приходят отключёнными |

Сценарии `boss_*` требуют отладочной сборки: `make clean && make DEBUG_BOSS=-1`. В ней есть
переменная `g_debug_forced_boss`, которую сценарий записывает до начала забега. Номер босса —
его значение в `enum BlindType` (`include/blind.h`), список реализованных есть в начале
`boss_round.txt`. Сборка с `DEBUG_BOSS=BLIND_TYPE_HOOK` (или номером) всегда даёт этого босса.
| `scenarios/modifiers.txt` | Сид `GBARU1`: все 52 карты с улучшениями и печатями (`gen_modifiers.py`), рука из 5 карт, подсчёт, Синяя печать создаёт Планету в конце раунда |
| `scenarios/packs.txt` | Сид `GBARU1`: Стандартный бустер в лавке (десятая лавка после 9 рероллов), описание, покупка, выбор 1 из 3, колода 53/53 |
| `scenarios/jokers_pair.txt` | Два джокера, которые всегда выпадают в лавке (`make DEBUG_JOKER0=<id> DEBUG_JOKER1=<id>`, перед сборкой `touch source/joker.c`): описания, покупка, две руки на Биг блайнде |
| `scenarios/tarot.txt` | Таро (нужна `make DEBUG_TAROT=1`): Сила и Смерть на выбранных картах, Звезда, Повешенный (колода 50), Башня (Каменная), Отшельник ($4 → $8), Суд создаёт джокера, Дурак копирует последнее Таро |
| `scenarios/tarot_shop.txt` | Сид `GBARU1`, 10-я лавка: бустер Аркана (3 Таро, название выбранного), Дурак в лавке с описанием, покупка, описание в ряду расходников |
| `scenarios/purple_seal.txt` | Фиолетовая печать у всех карт: сброс 2 карт создаёт 2 Таро, при полных слотах третий сброс ничего не создаёт |
| `scenarios/jokers_economy.txt` | Два джокера партии 2 (`make DEBUG_JOKER0=64 DEBUG_JOKER1=67`, `touch source/joker.c`): описания, покупка, победа в Биг блайнде одной рукой, строка «Джок.» и сумма «Забрать». С Трубадуром (72) видно 10 карт в руке и 3 руки |
| `scenarios/planets.txt` | Сид `GBARU1`: Планета в лавке (Плутон после трёх рероллов), описание, покупка, панель расходников, экран «Уровни рук» (SELECT), использование в раунде, Старшая карта 15×2 и счёт 52 за туза |

Команды сценария описаны в начале `gbarun.c`. Адреса можно писать символами:
`{sym:s_seed_str}` — адрес символа из ELF (в том числе static), `{gv:score}` — адрес поля
`g_game_vars.score`. Сид задаётся записью в `s_seed_str` и `use_seed` перед нажатием «ИГРАТЬ».

## Сравнение двух сборок

Изменение, которое не должно менять поведение (рефакторинг, заготовки API), проверяется так:
прогнать один и тот же сценарий на старой и новой сборке и сравнить скриншоты.

```bash
python3 ru-tools/emu/compare.py /tmp/shots_old /tmp/shots_new
```

Без фиксированного сида сравнивать нельзя: случайный сид берётся из аппаратного таймера,
и любое изменение кода меняет его.
