# Прогон рома в эмуляторе без экрана

Скриптовые smoke-тесты на mGBA: ром запускается без окна, кнопки нажимаются по сценарию,
скриншоты сохраняются в PNG. Подходит для проверки «Готово, когда» по фиксированному сиду
и для сравнения двух сборок кадр в кадр.

## Установка (Ubuntu)

```bash
sudo apt install libmgba-dev libpng-dev python3-pil
```

`run.py` сам соберёт `gbarun` из `gbarun.c` при первом запуске.

## Запуск

Сначала собрать ром (`docker compose run gbalatro`), потом:

```bash
python3 ru-tools/emu/run.py ru-tools/emu/scenarios/smoke_shop.txt /tmp/shots
```

Для адресов в сценарии нужен ARM-тулчейн. Если задан `$DEVKITARM`, `run.py` берёт его,
иначе запускает команды в образе проекта через `docker compose run gbalatro`.

## Сценарии

| `scenarios/smoke_shop.txt` | Сид `GBARU1`: блайнд пройден (счёт подставлен), награды, лавка, описание и покупка джокера, переход к следующему блайнду |
| `scenarios/smoke_lose.txt` | Сид `GBARU1`: четыре руки из пяти левых карт без подсказок, экран поражения |

| `scenarios/decks_plasma.txt` | Плазменная колода: цель 600 вместо 300, Старшая карта 16 x 1 выравнивается до 8 x 8, счёт 64 |
| `scenarios/black_deck_six_jokers.txt` | Чёрная колода: 6 джокеров в ряду, седьмой не покупается, продажа из полного ряда |
| `scenarios/boss_round.txt` | Выбранный босс (`-D boss=N`): подпись на экране выбора блайнда, раунд: 1 карта, 5 карт, сброс, снова 1 карта |

Сценарии `boss_*` требуют отладочной сборки: `make clean && make DEBUG_BOSS=-1`. В ней есть
переменная `g_debug_forced_boss`, которую сценарий записывает до начала забега. Номер босса —
его значение в `enum BlindType` (`include/blind.h`), список реализованных есть в начале
`boss_round.txt`. Сборка с `DEBUG_BOSS=BLIND_TYPE_HOOK` (или номером) всегда даёт этого босса.

| `scenarios/spectral.txt` | Спектральные карты в раунде (`make DEBUG_TAROT=1`): Фамильяр (колода 54), Знак, Талисман, Криптид (56), Сожжение (+$20, 51), Чёрная дыра (уровни рук), Обсерватория (15 x 3 у Старшей карты), Призрак (джокер, $0), Анх (копия) |

Команды сценария описаны в начале `gbarun.c`. Адреса можно писать символами:
`{sym:s_seed_str}` — адрес символа из ELF (в том числе static), `{gv:score}` — адрес поля
`g_game_vars.score`. Сид задаётся записью в `s_seed_str` и `use_seed` перед нажатием «ИГРАТЬ».

## Сравнение двух сборок

Изменение, которое не должно менять поведение (рефакторинг, заготовки API), проверяется так:
прогнать один и тот же сценарий на старой и новой сборке и сравнить скриншоты.

```bash
python3 ru-tools/emu/compare.py /tmp/shots_old /tmp/shots_new
```

Без фиксированного сида сравнивать нельзя: случайный сид берётся из аппаратного таймера,
и любое изменение кода меняет его.
