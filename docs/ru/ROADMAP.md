# План доработок русской сборки Balatro GBA

План распределён по агентам. Основа — форк `balatro-gba-ru` на v0.2.3. Работа идёт волнами: агенты одной волны работают параллельно, следующая волна стартует, когда в базовую ветку влита предыдущая.

**Статус:** волна 0 выполнена (см. «Итоги волны 0» в разделе A0), можно начинать волну 1.

## Общие правила для всех агентов

1. **Ветки.** У каждого агента своя ветка от актуальной базы (`agent/<имя>`). В базу их вливает только интегратор.
2. **Сборка.** Собирать через `docker compose run gbalatro`. Сборка должна проходить без новых предупреждений.
3. **Случайность.** Каждая новая случайная механика получает свою последовательность в `enum RngSequence` (`include/random.h`). Иначе ломается воспроизводимость по сиду, которую чинили в #599.
4. **Тексты.** Строки пишутся сразу по-русски в CP1251 и должны влезать в ширину 8×8 тайлов. Сокращения согласуются с агентом локализации (A10).
5. **Палитры и спрайты.** Палитры раздаёт только A10. Сейчас из 16 палитр 12 занято под джокеров (`include/joker.h`, `JOKER_BASE_PB`), а на экране лимит в 128 спрайтов (`MAX_SPRITES` в `include/sprite.h`).
6. **Проверка готовности для каждой задачи:**
   - забег по фиксированному сиду проходится до 8-го анте;
   - существующие 52 джокера работают как раньше;
   - новые функции на хост-машине покрыты тестами в `tests/`, если это возможно;
   - есть скриншот из mGBA.
7. **Горячие файлы.** `source/game/round.c`, `source/game/shop.c`, `source/game.c` и `include/game_variables.h` правят почти все. Их меняют только через API-заготовки из волны 0, никто не переписывает их целиком.

## Волна 0: фундамент (последовательно, блокирует все остальные волны)

### A0. Интегратор

**Цель:** подтянуть апстрим и заложить общие API, чтобы агенты дальше не конфликтовали.

1. **Синхронизация с апстримом.** Смёрджить `GBALATRO/balatro-gba` `main` в форк. Это даст:
   - теги за пропуск блайнда (#541, #641, #651, #664);
   - продажу предметов через Item API (#628);
   - перенос описаний джокеров на Item API (#613);
   - удаление кода изданий джокеров (#640);
   - новые имена клавиш (#645).

   Конфликты ожидаются в местах с переведёнными строками: `joker_effects.c`, `shop.c`, `blind_select.c`. При разрешении сохранять русский текст и брать логику из апстрима.
2. **Заготовки API.** Добавить пустые структуры и хуки без реальной логики. Это главный способ развести параллельных агентов по разным файлам:
   - **В `GameVariables`** (`include/game_variables.h`) новые поля: `joker_slots`, `consumable_slots`, `shop_slots`, `interest_cap`, `stake`, `hand_levels[]`, `owned_vouchers` (битсет).
   - **Замена жёстких констант на поля:** `MAX_JOKERS_HELD_SIZE` (`include/game.h`) → `joker_slots`, `MAX_INTEREST` → `interest_cap`.
   - **В `Card`** (`include/card.h`) новые поля: `enhancement`, `seal`, `debuffed`, `face_down`. Пока везде нули.
   - **`include/blind_effects.h`:** события босса по образцу событий джокеров (`ON_BLIND_SELECTED`, `ON_HAND_PLAYED`, `ON_CARD_DRAWN`, `ON_CARD_SCORED`, `ON_DISCARD`, `ON_ROUND_END`) и пустая таблица обработчиков на 28 боссов.
   - **В `enum ItemType`** (`include/item.h`): `ITEM_TYPE_CONSUMABLE`, `ITEM_TYPE_VOUCHER`, `ITEM_TYPE_PACK` и пустые реализации функций.
   - **Хук `deck_apply_start_effects()`** в начале забега.
3. **Инфраструктура.** Сделать workflow сборки ромов только по ручному запуску: автоматические триггеры в форке отключены, включать их обратно не нужно. Плюс шаблон чек-листа для PR.

**Готово, когда:** ром собирается, игра ведёт себя точно как v0.2.3 плюс теги из апстрима, а заготовки влиты в базу.
**Объём:** M.

#### Итоги волны 0

- **Сборка воспроизводима из репозитория.** Раньше релиз собирался с `-fexec-charset=CP1251` и локально пропатченной libtonc, а в репозитории не было ни того, ни другого. Теперь флаг стоит в `Makefile`, а замена `utf8_decode_char()` лежит в `source/cp1251_text.c`. Исходники пишутся в UTF-8, в ром строки попадают в CP1251.
- **Апстрим влит** до #665 включительно. Новые надписи переведены, в двух фонах русские подписи перенесены на новую палитру апстрима.
- **Заготовки API.** Без фиксированного сида поведение сравнить нельзя, поэтому проверено по сиду: скриншоты полного раунда, лавки и проигранного забега совпадают с версией до заготовок пиксель в пиксель.
  - `GameVariables`: `hands_per_round`, `discards_per_round`, `base_hand_size`, `joker_slots`, `consumable_slots`, `shop_slots`, `interest_cap`, `stake`, `hand_levels[]`, `owned_vouchers`. Это базовые значения забега, их сбрасывает `game_init()`. Руки, сбросы и размер руки в начале каждого раунда берутся из них, а не из констант.
  - Константы: `MAX_JOKERS_HELD_SIZE` и `MAX_SHOP_ITEMS` остались как ёмкость массивов и раскладки на экране, лимиты во время забега задают `joker_slots` и `shop_slots`. `MAX_INTEREST` заменён на `interest_cap`.
  - `deck_apply_start_effects()` (`deck_types.c`) вызывается из `game_start()` и меняет базовые значения забега.
  - `Card`: `enhancement` (`enum CardEnhancement`), `seal` (`enum CardSeal`), `debuffed`, `face_down`.
  - `ItemType`: `ITEM_TYPE_CONSUMABLE`, `ITEM_TYPE_VOUCHER`, `ITEM_TYPE_PACK` с заглушками в `item_funcs.c`. Такие предметы не появляются в лавке. При реализации заменить свою запись в `item_func_table`.
  - `blind_effects.h/.c`: события `BLIND_EVENT_*`, данные `BlindEventData`, флаги `BLIND_EFFECT_FLAG_*` и таблица обработчиков на 28 боссов. `round.c` уже вызывает все шесть событий, флаги пока не обрабатываются.
  - `stake.h`: список ставок.
- **Инфраструктура.** Все workflow запускаются только вручную. Добавлен шаблон PR с чек-листом (`.github/pull_request_template.md`) и прогон в эмуляторе по сценариям (`ru-tools/emu/`).

### A4. Уровни рук и ядро расходников с планетами

**Файлы:** `source/hand.c`, новые `source/consumable.c` и `include/consumable.h`, интеграция в лавку через Item API.

1. **Уровни рук.** Нужен массив `hand_levels[]` и прирост за уровень, как в оригинале: например, у пары +15 фишек и +1 множитель. Подсчёт очков берёт значение `base + level * increment` вместо `HAND_BASE_VALUES` (`source/hand.c`).
   - **Про `HAND_TYPE_MAX`:** выхода за границу нет. `HAND_TYPE_MAX = FLUSH_FIVE` — это последний тип руки, а не количество, и массивы по типам рук (`nb_played_hands[]`, `hand_levels[]`) индексируются как `hand_type - 1`. Так 13 элементов покрывают HIGH_CARD..FLUSH_FIVE. Новые массивы индексировать так же.
2. **Расходник.** Тип `ITEM_TYPE_CONSUMABLE` с подтипами PLANET, TAROT и SPECTRAL.
   - 2 слота в интерфейсе раунда и лавки.
   - Действия «использовать» и «продать».
   - Описание по удержанию B, как у джокеров.
3. **12 планет.** Секретные (Planet X, Ceres, Eris) появляются только после того, как сыграна соответствующая рука.
4. **Лавка.** Планеты появляются среди предметов верхнего ряда. Отдельная `RngSequence`.
5. **Экран «Уровни рук»** по кнопке, например SELECT в раунде.

**Готово, когда:** купленная планета прокачивает руку, и это видно по фишкам и множителю при подсчёте. Секретные планеты не выпадают раньше времени.
**Объём:** L. Это критический путь: от него зависят A5, A7 и A3.

### A9 (продолжение). Бесконечный режим

- Продолжать забег после победы на 8-м анте.
- Таблица требований `ANTE_LUT` (`source/blind.c`) кончается на 8-м анте, а счёт хранится в `u32`. Вариантов два:
  - **Простой:** продолжать до переполнения (около 11–12-го анте) и честно завершать игру.
  - **Полный:** своё число «мантисса + экспонента» и вывод в экспоненциальной записи.
- Рекомендую начать с простого.
- **Сделано (простой вариант, ветка `endless-bugfix-2`):** таблица до анте 12 (`include/ante_table.h`), «Дальше» на экране
  победы 8-го анте, финальная победа на 12-м анте, сценарий `endless.txt`, хост-тест `tests/ante_table`. Значения анте 9–12
  посчитаны по формуле оригинала и округлены до двух значащих цифр.
